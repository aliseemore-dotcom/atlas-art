# 06 — Очередность реализации для Claude Code

## Фаза 0: Foundation
Инициализировать Next.js + strict TS + Tailwind + ESLint + Vitest + Playwright. Добавить Docker Compose с PostgreSQL (локально), `.env.example`, команды `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`, инструкции миграций. Первую страницу и tokens.

## Фаза 1: Data + chronology (главная ценность)
Создать Prisma schema (Artist, Movement, Genre, Region, связи), миграцию и валидируемый CSV seed. Реализовать `/regions/russia` с настоящим временным масштабом, zoom/pan, поиском/фильтрами, переключением списка/оси, карточками авторов и API. Тесты координат, интервалов и поиска. Это первая демонстрируемая версия.

## Фаза 2: Art history graph
Добавить Group, ArtistRelationship, MovementRelationship, Source, FactCitation; админские процедуры добавления подтверждённых связей; дерево течений и граф отношений. Не выводить бездоказательные стрелки.

## Фаза 3: Artwork and reference
Добавить Artwork и карточки работ, лицензионную политику, источники, placeholder при отсутствии прав; отметить 3–5 ключевых работ там, где их атрибуция проверена.

## Фаза 4: Learning
Добавить Auth, прогресс, заметки, маршруты и короткие тесты. Поддержать импорт содержания пользовательской книги с привязкой к художникам/эпохам.

## Фаза 5: Global expansion
Расширить на мировые художественные традиции с общей шкалой и мульти-региональным интерфейсом. Начать с выбранных стран после подтверждения глубины каталога.

## Стоп-условия перед переходом к следующей фазе
Пройдены acceptance tests текущей фазы, миграции повторяемы, seed идемпотентен, состояния ошибок обработаны, мобильный сценарий работает, документация запуска актуальна.

## Готовые промпты Claude Code
**Старт:** «Прочитай CLAUDE.md и docs/*.md. Реализуй фазу 0 и 1. В конце покажи изменённые файлы и результаты команд. Не используй случайные изображения, не выдумывай биографические связи».

**Фаза 2:** «На базе рабочего MVP1 реализуй только фазу 2 из docs/06_IMPLEMENTATION.md. Добавь типизированные связи с источниками и две отдельные визуализации. Не создавай связи из совпадения дат».

**Ревью:** «Сверь реализацию с docs/05_ACCEPTANCE.md. Запусти typecheck, lint, unit/e2e. Составь таблицу: требование, статус, доказательство, исправление. Затем исправь критичные проблемы».
