# ATLAS ART — пакет документации для Claude Code

## Что строим
Интерактивный обучающий атлас истории изобразительного искусства. Первый полноценный региональный модуль — Русь / Российская империя / СССР / современная Россия с возможностью показывать смежные художественные традиции и будущим расширением на мировую историю искусства.

**Ключевой UX:** (1) общая хронология, (2) дерево художественных направлений, (3) граф подтверждённых влияний, (4) карточка художника и произведения, (5) личный прогресс.

## Вход в разработку
1. Прочитай `CLAUDE.md` — правила для AI-разработчика.
2. Прочитай `docs/01_PRODUCT.md` — требования и сценарии.
3. Прочитай `docs/02_ARCHITECTURE.md` и `docs/03_DATA_MODEL.md`.
4. Прочитай `docs/04_UI_AND_GRAPH.md` и `docs/05_ACCEPTANCE.md`.
5. Начни с фазы 1 из `docs/06_IMPLEMENTATION.md`. Не реализуй всё в одном коммите.
6. Для начального наполнения используй `data/artists_seed.csv`. Это **черновой учебный набор**, не подтверждённый каталог: не публикуй карточки со статусом `needs_review` как проверенную энциклопедию.

## Быстрый запуск с Claude Code
Открой эту папку как проект и отправь Claude Code:

> Прочитай README.md, CLAUDE.md и документацию в docs/. Выполни фазу 1 из docs/06_IMPLEMENTATION.md: инициализируй приложение, настрой БД, создай схему и сидирование, сделай страницу хронологии с реальными данными из PostgreSQL. Работай итеративно, запускай тесты и показывай итог каждой фазы. Не придумывай факты о художниках. Если ключей доступа нет — оставь .env.example и опиши шаги настройки.

## Запуск (фазы 0–1)

Нужны Node 20+ и PostgreSQL 16 (через Docker или локально).

```bash
cp .env.example .env        # DATABASE_URL для локальной базы; секреты в репозиторий не попадают
npm install
npm run db:up               # PostgreSQL в Docker (или запустите свой и поправьте DATABASE_URL)
npm run db:migrate          # применить миграции
npm run db:seed             # идемпотентный импорт data/artists_seed.csv (114 черновых записей)
npm run dev                 # http://localhost:3000/regions/russia
```

| Команда | Что делает |
|---|---|
| `npm run lint` / `typecheck` | ESLint / `tsc --noEmit` |
| `npm test` | unit и компонентные тесты (Vitest) |
| `npm run test:e2e` | сценарии Playwright (десктоп и 360 px); `PLAYWRIGHT_CHROMIUM_PATH` — путь к своему Chromium |
| `npm run db:reset` | пересоздать базу и миграции (только локально) |

Импорт: CSV → валидация Zod → upsert по постоянному `seedId` → журнал ошибок. Записи со статусом `verified`
не перезаписываются черновыми данными. Повторный запуск не создаёт дублей.

Что в фазе 1: `/regions/russia` (шкала с zoom/pan, список, поиск без учёта регистра и ё/е, фильтры год/жанр/направление
в URL), `/artists/[slug]`, `/movements/[slug]`, `GET /api/artists`, `/api/timeline`, `/api/artists/[slug]`, `/api/movements`.
Все записи в наборе — `needs_review`; в интерфейсе они так и помечены.
