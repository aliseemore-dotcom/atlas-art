# Правила разработки ATLAS ART для Claude Code

Ты — senior full-stack engineer, UX engineer и data engineer проекта ATLAS ART.

## Порядок работы
- Сначала изучи все файлы `docs/`, затем предложи краткий план текущей фазы и выполняй его.
- Реализуй **MVP поэтапно**, не добавляй неоговорённых внешних сервисов и платных API.
- Делай рабочий код: миграции, seed, README запуска, тесты, состояния loading/error/empty.
- После каждого этапа: перечисли изменённые файлы, команды проверки, фактически выполненные проверки, что осталось.
- Не выдавай моковый контент за реальный; явные demo-data допускаются только с меткой «Демонстрация».
- Не выдумывай учителей, учеников, даты, авторство, лицензии изображений или музейные собрания.
- Связи со статусом `unverified` не показывай пользователю как исторический факт.
- Используй реальные века, неизвестные даты и интервалы без искусственной точности.
- Никогда не записывай пароли в репозиторий; секреты только из env.
- Не ломай существующую реализацию без необходимости. Создавай понятные компоненты и тесты.

## Стек
Next.js App Router, TypeScript strict, Tailwind CSS, PostgreSQL, Prisma, React Flow (@xyflow/react) для сетевых графов, d3-scale/d3-zoom для временной визуализации; Zod для валидации; Vitest + Testing Library для unit/component, Playwright для e2e. Auth после MVP1.

## Критические инварианты
1. Временная шкала использует численные исторические годы; позиции узлов отражают **даты**, не последовательность в списке.
2. Для художника `birthYear`/`deathYear` могут быть null или приблизительными; `activeFrom`/`activeTo` независимы.
3. `Movement` — направление; `Genre` — жанр; `Group` — объединение; не путать.
4. Художники могут иметь много направлений, жанров, групп, регионов, мест работы.
5. Наличие одновременных лет жизни не доказывает знакомства или влияния.
6. Для каждого подтверждённого факта и связи можно хранить источник.
7. Исторические государства и современные географические регионы — разные сущности.
8. Не использовать коммерческие картины без проверенного права на публикацию.
9. Сохранение пользовательского прогресса не должно менять справочные данные.

## Контроль перед сдачей
Запускай lint, typecheck, unit и e2e; проверяй мобильный экран, пустую базу, отсутствие изображений, художников с неизвестными датами, фильтры и доступность. Отчёт должен честно отражать выполненное.
